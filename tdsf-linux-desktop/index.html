本机 远端会话 命令下发 / 输出回推 被风险闸拦下

难的不是记命令，
是按下回车之前那段空白

教程给不了失败样本，聊天框给不了执行现场，终端什么都不解释。 这个工作台把三件事接起来：命令在哪里执行、执行前后发生了什么、哪些命令不该执行。

拦在按下回车
之前，不是事后
没有这道闸的时候
$ rm -rf /var/log　→ 三分钟后发现日志没了，且没有撤销
$ curl … | bash　→ 脚本内容没人看过，已经在跑了
$ chmod 777 /etc → 报错之前，权限已经放开

初学者的代价通常是“这台虚机废了，重装”。教学环境里，这等于放弃动手。

现在发生的顺序

先分词，再切段。引号里的 ; | && 不算分隔符， 所以 bash -c "rm -rf /; echo x" 不会被撕成两段绕过。

写法变体同判。rm -rf /、rm -rf "/"、 rm -rf // 归一后再比受保护清单。

三个入口一条闸。人敲的、粘贴的、AI 发起的命令，都从同一个执行口出去。

拦下要能说清。每次拦截留痕：命中哪条规则、为什么、替代做法是什么。

八项能力，
每项都对得上界面上真存在的入口

未接线的占位功能不写在这里。没有生产者的统计值不显示在界面上。

8 项
每项都有界面入口
terminal

终端优先，不是聊天框优先

三栏可拖拽，终端格默认最大化；多标签、独立第二窗口，同时看两台机器不来回切。拖出来的宽度会记住。

blocks

命令与输出切成块

OSC 133 / 633 标记把一次命令和它的输出缝成一块，可回看、可检索，也是 AI 读上下文的单位。

gate

拦截发生在执行之前

词表规则 + tree-sitter-bash 结构化解析 + 只读白名单，输出等级、命中依据、影响范围；拦下的那些不会落进 shell。

agent

AI 的每一步落在屏上

思考、工具调用、待执行命令、返回结果分开展示；诊断 / 部署 / 巡检 / 回滚四种模式走同一套编排，流式可中断。

context

用量说清是实测还是估算

上下文占用按模型真实窗口计算；实测 token 与估算值分开标注，不拿估出来的数字冒充实测。

decide

结论后面挂着证据链

多源证据加权融合（Dempster 规则 + PCR5 冲突再分配），雷达图显示每条证据的贡献与冲突流向；权重读取失败时降级为无权重融合，界面如实显示降级。

knowledge

断网也能查的运维知识

命令词典、教程、故障案例三类条目；本地嵌入模型 + SQLite 向量索引做语义检索，不依赖外部 API。读者答复回灌条目成功率。

local

数据与凭据留在本机

服务器信息、历史、知识库存在本地 SQLite；凭据只在主进程边界内使用，日志、报错、AI 上下文出边界前统一脱敏。

Electron 安全三原则保持不动

  • contextIsolation: true
  • nodeIntegration: false
  • sandbox: true

新增能力优先落在主进程。日志、报错、AI 上下文在离开进程边界前统一脱敏；凭据不进渲染层，也不进任何文本产物。

一条 AI 建议从生成到执行

这是产品的核心承诺：任何改动远端状态的命令，都要走完这四步才会落到终端。

4 步
改远端状态都要走完
1

生成

模型基于终端上下文、命令块历史与知识库给出建议，工具调用在流式过程中即时展示，不事后补写。

2

判定

命令进风险引擎：词表 + AST + 只读白名单，输出风险等级、命中依据与影响范围。

3

确认

决策卡由主进程构造——模型无法伪造自己的“已批准”。界面显示准备执行什么、在哪台机器、失败怎么回滚。

4

留痕

执行结果与当时的证据构成写入本地记录，事后在决策页可回查；被拦下的同样留痕，含原因。
