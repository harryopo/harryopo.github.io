让第一次连上 Linux 服务器的人，
敢敲下一条命令

TDSF-Linux Desktop 把 SSH 终端、AI 助手、高危命令拦截与决策留痕放进同一个窗口。 AI 不替你按下回车——它先说清要执行什么、依据是什么、失败会怎样，再由你确认； 你自己敲的命令同样会过一遍风险检查。

Electron 43 + React 19 终端 xterm.js + 命令/输出分块 模型 可指向本机 Ollama 数据 只存本机 SQLite

为什么是这样一个工具

初学 Linux 时最难的不是记命令，而是"这条命令按下去会发生什么"。 教程给不了失败样本，AI 聊天给不了执行现场，终端又什么都不解释。 这个工作台把三件事接在一起：命令在哪里执行（本机 / 远端 / 第几个标签页）、 执行前后发生了什么（命令与输出被切成块，可回看可检索）、 哪些命令不该执行（结构化解析 + 规则库判定，拦截后留下可读的原因）。

终端优先

界面围绕会话，而不是围绕聊天框

三栏可拖拽布局，终端格默认最大化；左侧资源管理器，右侧 AI 面板可随时收起。多终端标签、独立第二个窗口，同时看两台机器不用来回切。

可见执行

AI 的每一步都落在屏上

思考过程、工具调用、待执行命令、返回结果分开展示；上下文占用按模型真实窗口计算，用量与估算分开标注，不拿估出来的数字冒充实测。

核心能力

以下每一项都对应界面里真实存在的入口，未接线的占位功能不写在这里。

01 · 终端

SSH 与本机终端，同一套语义

  • xterm.js 渲染，Fit / Search / 链接识别插件
  • 本机终端走 node-pty，远端走 ssh2，两侧命令块口径一致
  • OSC 133 / 633 标记切分"命令—输出"块，供 AI 与历史检索消费
  • 跳板机连接同样校验主机密钥
02 · 命令安全

拦截发生在执行之前

  • 规则以数据文件维护：10 类判定、200 余条判定项
  • tree-sitter-bash 做结构化解析，绕过词表的写法（重定向、命令替换、find -exec）另走一层
  • 人敲的、粘贴的、AI 发起的命令过同一道闸
  • 每次拦截留痕，给出原因与替代建议
03 · AI 助手

流式、可中断、可降级

  • 诊断 / 部署 / 巡检 / 回滚四种工作模式，PAOR 循环编排
  • 24 个受控工具（SSH、日志、监控、知识库、可信度、沙箱审批）经主进程派发
  • 请求级总超时 + 单一重试栈，重试不重复推送已吐出的字
  • 模型侧失败时给出可操作的降级路径，而不是一个红色报错
04 · 可信决策

结论后面挂着证据链

  • 多源证据加权融合（Dempster 规则 + PCR5 冲突再分配）
  • 雷达图显示每条证据的贡献与冲突流向，可逐项展开
  • 决策记录持久化，事后能查"当时依据是什么"
05 · 知识库

离线可查的运维知识

  • 命令词典、教程、故障案例三类条目，断网可用
  • 本地嵌入模型 + SQLite 向量索引做语义检索，不依赖外部 API
  • 读者答复（有帮助 / 没帮助）回灌条目成功率，逐次累积
06 · 监控与日志

这台机器现在怎么样

  • CPU / 内存 / 磁盘 / 网络定时采样，阈值可配
  • 告警按"会话 + 种类"稳定编号，标记已处理会真的改变状态，指标回落后自动作废
  • 日志分析、系统事件与操作历史可交叉检索
07 · 文件与预览

改远端文件不必离开窗口

  • SFTP 文件树 + Monaco 编辑器，编辑器资源本地打包，不请求 CDN
  • 路径写入范围受限，越界操作需要先经确认
  • 预览面板经 SSH 端口转发打开远端服务，句柄协议限制可访问范围
08 · 本地优先

数据与凭据留在本机

  • 服务器信息、历史、知识库存在本地 SQLite，凭据只在主进程边界内使用
  • 日志、报错、AI 上下文出边界前统一脱敏
  • 模型可指向本机 Ollama，全链路不出内网

架构

三进程分离。渲染层拿不到 Node 能力，所有敏感操作经 preload 暴露的类型化通道进入主进程； 通道清单由单一契约文件生成，渲染层与主进程共用同一份类型。

主进程 · Node.js

能力与判定

SSH2 连接池、node-pty、SQLite、风险引擎、可信度融合、LLM 客户端、MCP 服务、调度器。

Preload · contextBridge

受控边界

283 个 IPC 通道由契约生成，入参在入口做严格校验，错误以统一信封返回。

渲染进程 · React 19

界面与状态

Zustand 状态容器，Radix + Tailwind 组件层，设计令牌单一来源，深浅两套主题都过对比度检查。

沙箱三原则保持不动：contextIsolation 开启、nodeIntegration 关闭、sandbox 开启。 新增能力优先落在主进程，渲染层只负责呈现与发起请求。

一条 AI 建议从生成到执行

这条链路是产品的核心承诺：任何改动远端状态的命令，都要走完这四步才会落到终端。

生成

模型基于终端上下文、命令块历史与知识库给出建议，工具调用在流式过程中即时展示，不事后补写。

判定

命令进风险引擎：词表规则 + bash AST 解析 + 只读白名单，输出风险等级、命中依据与影响范围。

确认

决策卡由主进程构造（模型无法伪造自己的"已批准"），界面显示准备执行什么、在哪台机器、失败怎么回滚。

留痕

执行结果与当时的证据构成写入本地记录，事后在决策页可回查；拦截同样留痕，包含被拦下的原因。

当前状态与边界

  • 项目仍在持续开发，源码仓库当前为私有状态，暂未公开发布安装包；需要试用或源码请通过下方联系方式沟通。
